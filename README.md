# Jeti Nur Реклама

Telegram-бот `@jeti_nur_reklama_bot`, MVP с интерфейсом v1.1 по `TZ_reklama_bot_MVP_v1.md`. Реализованы все пять этапов: каталог, заказы с чеками, удаление заказов, аналитика, Word-отчёты и ручной бэкап.

Все сотрудники из whitelist работают с общим каталогом и списком заказов. Язык ru/ky сохраняется отдельно для каждого пользователя. Ролей и подтверждения заказов администратором нет.

## Требования

- Python 3.10–3.12; рекомендуется 3.11.
- Доступ к Telegram API и токен от BotFather.
- Для контейнера — установленный Docker Engine или Docker Desktop.

Используются aiogram 3 (polling), aiosqlite, python-dotenv, matplotlib (Agg), python-docx и tzdata. Домен, webhook и SSL не нужны. Word и LibreOffice на сервере для генерации отчётов не требуются.

## Установка и запуск локально

В корне проекта, для новой установки:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp -n .env.example .env
```

Для Python 3.10 или 3.12 замените первую команду на соответствующий интерпретатор. В Windows активируйте окружение командой `.venv\Scripts\activate` и скопируйте `.env.example` вручную, если `.env` ещё нет.

На текущем компьютере уже подготовлены `.runtime/` с Python 3.11 и `.venv/` со всеми зависимостями. Для обновления и запуска достаточно:

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m bot.main
```

Эти команды используют уже заполненный `.env`. При переносе проекта на другой компьютер создайте окружение заново. `.runtime/` и `.venv/` исключены из Git.

Остановка — `Ctrl+C`. Запускайте один polling-процесс на токен: перед переходом на Docker остановите локальный бот.

## Настройка .env и получение ID

1. Откройте [@BotFather](https://t.me/BotFather). Для нового бота выполните `/newbot`; для существующего откройте `/mybots` → бот → API Token. Запишите токен в `BOT_TOKEN`.
2. При первом запуске можно оставить `ALLOWED_USER_IDS=` пустым: доступен только `/myid`.
3. Запустите `python -m bot.main`, отправьте боту `/myid` и получите свой числовой Telegram ID.
4. Добавьте ID в `.env`: `ALLOWED_USER_IDS=111111111`. Для двух сотрудников — `ALLOWED_USER_IDS=111111111,222222222`.
5. Перезапустите процесс, отправьте `/start` и выберите **Русский** или **Кыргызча**.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | отсутствует | Обязательный токен BotFather |
| `ALLOWED_USER_IDS` | пусто | Положительные Telegram ID через запятую; пусто — только `/myid` |
| `DB_PATH` | `data/bot.db` | Постоянный файл SQLite; относительный путь считается от корня проекта |
| `BOT_TZ` | `Asia/Bishkek`, если обе переменные пусты | Часовой пояс отображения и календарных периодов; имеет приоритет над `TZ` |
| `TZ` | значение контейнера или не задано | Запасной часовой пояс, если `BOT_TZ` отсутствует или пуст |
| `DEFAULT_LANG` | `ky` | Язык до выбора: `ru` или `ky` |
| `ACCESS_DENIED_REPLY` | `false` | Старый параметр для совместимости; v1.1 всегда игнорирует посторонних молча |

Переменные окружения имеют приоритет над `.env`. Для применения изменений перезапустите локальный процесс; в Docker пересоздайте контейнер с новым `--env-file`. Сохранённый язык пользователя важнее `DEFAULT_LANG`.

Часовой пояс выбирается в порядке **BOT_TZ → TZ → Asia/Bishkek**; пустые значения пропускаются. Поэтому `BOT_TZ=Asia/Bishkek` в `.env` задаёт время бота даже при контейнерном `TZ=Europe/Amsterdam`. Переменная `BOT_TZ` в окружении имеет приоритет над одноимённой переменной в `.env`. При старте в логах выводится фактически выбранный пояс: `Database initialized: ...; timezone: Asia/Bishkek`.

`.env`, базы данных и локальные окружения исключены из Git и контекста Docker. Образ содержит код `bot/` и зависимости; токен передаётся при запуске через окружение.

## Команды и работа с ботом

| Команда | Доступ | Действие |
|---|---|---|
| `/start`, `/menu` | whitelist | Главное меню; прекращают текущий диалог |
| `/language` | whitelist | Сменить язык |
| `/edit` | whitelist | Режим редактирования каталога: добавить, изменить, удалить карточку |
| `/deleteorder` | whitelist | Открыть карточки заказов для удаления |
| `/myid` | все | Telegram ID отправителя |
| `/cancel` | whitelist | Отменить незавершённое действие |
| `/backup` | whitelist | Скачать согласованную копию SQLite |

Нижняя постоянная клавиатура содержит только две вертикальные кнопки: **📋 Каталог** и **📊 Аналитика**. Menu Telegram показывает `/start`, `/menu`, `/language`, `/edit`, `/deleteorder`, `/myid`, `/cancel`: описания по умолчанию кыргызские, для русского интерфейса Telegram — русские. `/backup` доступен по вводу команды. Сообщение «Главное меню / Башкы меню» появляется только при `/start` или `/menu`; выбор языка доставляет клавиатуру вместе с подтверждением.

**Каталог.** По «📋 Каталог» сразу появляются жирные карточки «Название — цена сом», каждая с одной кнопкой «✅ Выбрать / ✅ Тандоо» на всю строку. Кнопок изменения, удаления и добавления здесь нет. Если каталог пуст, бот показывает «Каталог пуст / Каталог бош» и подсказку отправить `/edit`.

**Редактирование каталога.** Команда `/edit` сначала показывает «✏️ Режим редактирования / ✏️ Өзгөртүү режими», затем жирные карточки с кнопками «✏️» и «🗑» в одном ряду, без выбора продукта. В конце — пояснение «Чтобы добавить карточку, нажмите кнопку ниже / Жаңы карточка кошуу үчүн ылдыйдагы баскычты бас» и кнопка «➕ Добавить карточку / ➕ Карточка кошуу». В пустом редакторе также сохраняются сообщение о пустоте и блок добавления. `/edit` есть в списке команд Telegram и в подсказке `/menu`; нижнее меню остаётся из двух кнопок.

Добавление и изменение проходят прежние шаги: название — 1–60 символов; цена — больше 0 и меньше 1 000 000, с точкой или запятой. Товар сохраняется после правильной цены. Подтверждение удаления содержит только «Да/Нет» или «Ооба/Жок». «Нет» заменяет подтверждение текстом «Удаление отменено / Жокко чыгарылды» без его кнопок; «Да» устанавливает `is_active = 0` и не меняет старые заказы. После добавления, изменения, удаления или отмены формы бот показывает обновлённый редактор. Неверный ввод оставляет соответствующий шаг открытым. Обычный каталог и завершение/отмена заказа возвращают карточки только с выбором продукта. `/edit` обрабатывается до FSM и fallback: команда не удаляется и прекращает предыдущий незавершённый диалог.

**Заказ.** Нажмите «Выбрать», затем отправьте чек как фото или документ. Другие типы удаляются с напоминанием; состояние ожидания сохраняется. «Назад» находится под запросом чека; отмена в формах каталога тоже inline, поэтому нижние две кнопки всегда остаются. До чека заказ не существует; «Назад» и `/cancel` возвращают в каталог без сохранения. Название и цена фиксируются при выборе продукта. Сохраняются Telegram `file_id`, `file_unique_id`, тип и имя документа, автор и UTC-время создания. Чек не проверяется автоматически и не скачивается на сервер.

**Удаление заказа.** Команда `/deleteorder` открывает карточки без заголовка. В общем списке последние 10 неудалённых заказов, с пагинацией `◀ ▶`. Карточки нумеруются 1–10, 11–20 и далее. Нажатие «Удалить / Өчүрүү» редактирует эту же карточку в подтверждение «Да / Нет»; «Нет» восстанавливает карточку, «Да» заменяет её текстом об удалении. Пагинация появляется только при числе заказов больше 10. Удаление сохраняет `deleted_at` и `deleted_by`; запись и данные чека остаются в базе. Старая кнопка подтверждения не удаляет другой заказ. Удалённые записи исключены из всех результатов аналитики и Word-отчётов.

Незавершённые диалоги хранятся в памяти и сбрасываются при перезапуске. Языки, каталог, заказы, чеки и отметки удаления хранятся в SQLite. `init_db()` создаёт таблицы без демоданных и не очищает существующие записи.

## Аналитика и периоды

Нажмите **📊 Аналитика**: одно сообщение «Выберите период / Убакытты тандаңыз» с кнопками **Сегодня, 7 дней, 30 дней, ✏️ Ввести число, За всё время**. Ввод числа принимает только целые **1–99**; при ошибке бот просит повторить, `/cancel` отменяет ввод.

После выбора сразу появляется одна сводка: период, количество заказов, сумма. Под сводкой:

- **🏆 Топ** и **📈 График** в одном ряду;
- **🧾 Список с чеками / 🧾 Тизме чек менен**;
- **📄 Word**;
- **🔄 Сменить период / 🔄 Убакытты өзгөртүү**.

Разделы используют выбранный период без повторного вопроса. Ключ периода, UTC-граница и номер страницы находятся в `callback_data`, поэтому кнопки работают после перезапуска и не зависят от FSM. Для обновления границ выберите период заново.

- **Сегодня** — с 00:00 местного дня до момента выбора периода в часовом поясе бота (`BOT_TZ`, запасной `TZ`).
- **N дней** — сегодня и N−1 предыдущих календарных дней, с полуночи.
- **За всё время** — вся история до момента выбора периода.
- Границы переводятся в UTC; при `Asia/Bishkek` 13 октября начинается 12 октября в 18:00 UTC.
- Удалённые заказы исключены из суммы, топа, графика, списка и Word.

Топ группируется по сохранённому названию: `1. Машина: 15 раз, 3 000 сом` / `1. Машина: 15 жолу, 3 000 сом`. Переименование каталога не меняет старые заказы.

PNG-график до 31 дня строится по местным дням, более 31 дня — по неделям с понедельника. Для всей истории группировка зависит от её длительности. Крайние недели ограничены выбранным периодом; пропуски заполняются нулями. Белый фон, локализованные подписи, Agg и `plt.close()` после отправки, в том числе при ошибке.

В списке новые заказы сверху, по 10 на странице. Карточка:

```text
1. Машина — 200 сом
12:00 · 13.10.2026 · Имя
```

Первая строка жирная, вторая курсивная; название и имя экранируются для HTML. Нумерация сквозная. Под каждым заказом «🧾 Чек»: фото или документ по `receipt_type`. Стрелки `◀ ▶` появляются только при числе записей больше 10; текста с номером страницы и дополнительных кнопок под непустым списком нет. При пустом периоде — «За этот период заказов нет / Бул убакытта заказ жок» с возможностью сменить период.

## Удаление лишних сообщений

Последний fallback-хендлер удаляет неожидаемые сообщения пользователей из whitelist: голосовые, видео, кружки, аудио, стикеры, GIF, контакты, геолокацию и фото/документы/текст вне ожидаемого состояния. Ошибки удаления не прерывают работу бота. Команды, нижнее меню, текст в формах каталога и вводе дней, фото/документы ожидаемого чека сохраняются. Посторонние игнорируются молча; `/myid` остаётся доступен всем.

## Word-экспорт

Нажмите **Аналитика → период → 📄 Word**. Файл: `report_<период>_<дата>.docx`, например `report_15_2026-10-14.docx`; код периода — число 1–99 или `all`.

Документ на ru/ky оформлен как светлый отчёт: A4, поля 2 см, Calibri 11 с альтернативой Arial, явные цвета текста и белый фон страницы. По центру заголовок 22 pt; под ним период и местная дата формирования без названия часового пояса. В кыргызской версии используется «Убакыт».

В непустом отчёте:

- двухъячеечный блок количества и суммы;
- таблица топ-5: №, название, количество, сумма;
- встроенный белый PNG-график 200 dpi, по центру, ширина 16 см и подпись;
- таблица всех заказов: №, время/дата, продукт, сумма, автор; итоговая строка;
- номера страниц по центру нижнего колонтитула.

Таблицы имеют заданные ширины колонок, синюю шапку с белым текстом, чередование белых/светло-серых строк и тонкие границы. Суммы выровнены вправо. Чеки и их метаданные в отчёт не входят. **Пустой отчёт содержит заголовок, период/дату и пометку об отсутствии заказов, без таблиц и графика.**

Все части отчёта читаются из одной SQLite-копии: параллельное удаление не рассогласует итоги и таблицы. Строки читаются порциями; шапки повторяются на следующих страницах. Временные файлы удаляются после отправки или ошибки. В DOCX проверяются встроенный PNG, ссылка на него, размеры изображения, фон, цвета, ширины таблиц и поле PAGE. Отдельные просмотрщики могут принудительно менять цвета в своём ночном режиме; это настройка приложения, которую DOCX не может запретить.

## Резервная копия и восстановление

Отправьте **`/backup`** с аккаунта из whitelist. Бот создаст копию через SQLite Backup API и отправит `backup_<дата>_<время>.db`. Рабочий файл напрямую не отправляется. Копия включает пользователей, весь каталог, заказы, отметки удаления и данные чеков, в том числе изменения, находящиеся в WAL. Сами файлы чеков остаются в Telegram. Токен и настройки `.env` в базе не хранятся.

Сохраните полученный документ отдельно от сервера. Для восстановления:

1. Остановите бот.
2. Поместите скачанную копию под новым, ещё не существующим именем, например `data/restored.db`; так прежняя база остаётся сохранённой.
3. Для локального запуска установите `DB_PATH=data/restored.db` в `.env`. В Docker смонтируйте эту же папку и передайте `--env DB_PATH=/data/restored.db`.
4. Запустите бот. Таблицы уже есть; `init_db()` сохранит восстановленные данные.

Изменение `DB_PATH` переключает бота на другой файл. Новая пустая база не означает потерю прежней: проверьте путь к используемому файлу.

## Деплой на fps.ms

Выберите **Python container** и Python **3.10, 3.11 или 3.12** (рекомендуется 3.11). В корень сервера `/home/container` загрузите:

```text
/home/container/
  app.py
  requirements.txt
  bot/                    # весь Python-код, включая __init__.py и services/
  .env
```

**Не загружайте** `.venv/`, `.runtime/`, `venv/`, `__pycache__/` (включая вложенные папки), `tests/`, `data/`, `.git/` и локальные файлы баз. `requirements-dev.txt` на сервере не нужен.

В Startup укажите точку входа **app.py**; эквивалентная команда — `python -u app.py`. fps.ms устанавливает `requirements.txt` при старте. Это соответствует [официальной инструкции fps.ms](https://docs.fps.ms/telegram-bots/installation). Поле Additional Python packages оставьте пустым: зависимости уже перечислены в файле.

`requirements.txt` содержит только runtime-пакеты с закреплёнными версиями. Опция `--only-binary=:all:` распространяется и на их зависимости: pip использует готовые wheels без компиляции. Загрузка всех wheels проверена для CPython 3.10 / 3.11 / 3.12, Linux x86-64 с glibc 2.28+. Matplotlib работает через Agg; установка gcc, GUI, Word или LibreOffice не нужна. Тесты используют стандартный `unittest`, дополнительных dev-пакетов нет.

Создайте `.env` в `/home/container` или загрузите настроенный файл:

```dotenv
BOT_TOKEN=ВАШ_ТОКЕН_ОТ_BOTFATHER
ALLOWED_USER_IDS=111111111,222222222
DB_PATH=data/bot.db
BOT_TZ=Asia/Bishkek
DEFAULT_LANG=ky
ACCESS_DENIED_REPLY=false
```

Замените токен и ID на реальные значения. При пустом whitelist сначала используйте `/myid`, затем добавьте ID и перезапустите сервер. Переменные панели/окружения имеют приоритет над `.env`.

На fps.ms используйте именно `BOT_TZ`: заданный контейнером `TZ=Europe/Amsterdam` тогда не влияет на время бота. После старта проверьте в Console строку `timezone: Asia/Bishkek`.

`.env` и относительный `DB_PATH` считаются от корня проекта, независимо от рабочей папки процесса. На сервере база будет `/home/container/data/bot.db`; `data/` создаётся автоматически. Первая установка без базы начинает с пустого каталога. При обычном перезапуске и обновлении кода сохраняйте серверную папку `data/`. Логи выводятся в stdout и доступны в Console.

Перед Start остановите локальную копию бота и другие контейнеры с тем же токеном. При ошибке `Conflict: terminated by other getUpdates request` бот пишет, что в другом месте работает вторая копия, прекращает polling после первого конфликта и завершает процесс с кодом **0**. Внутренних повторов или перезапусков после конфликта нет; обычные временные сетевые ошибки продолжают повторяться. Если панель принудительно перезапускает даже нормально завершённые процессы или настроены расписания рестартов, остановите сервер в панели и отключите эти повторы до устранения второй копии.

**Обновление кода:**

1. Сохраните резервную копию через `/backup`, затем нажмите Stop в панели.
2. Замените `app.py`, `requirements.txt` и файлы внутри `bot/`. Сохраните серверные `.env` и `data/`; не очищайте весь каталог сервера и не загружайте локальную базу поверх серверной.
3. Нажмите Start: зависимости будут установлены по обновлённому `requirements.txt`.
4. В Console проверьте путь базы и начало polling, в Telegram — `/menu` и существующие карточки. При конфликте сначала остановите вторую копию, затем запускайте вручную.

Локальный `python -m bot.main` продолжает работать; `python app.py` использует тот же запуск. Деплой в аккаунт fps.ms здесь не выполнялся.

## Запуск в Docker

Команды ниже используют текущую папку `data/` как постоянный bind mount. Предполагается, что локальная база — `data/bot.db`; если путь другой, подставьте фактическую папку и имя файла. Остановите локальный polling-процесс перед запуском контейнера.

```bash
mkdir -p data
docker build -t jeti-nur-reklama .
docker run -d \
  --name jeti-nur-reklama \
  --restart unless-stopped \
  --user "$(id -u):$(id -g)" \
  --env-file .env \
  --env DB_PATH=/data/bot.db \
  --mount "type=bind,source=${PWD}/data,target=/data" \
  jeti-nur-reklama
```

Числовые UID/GID позволяют контейнеру писать в папку от имени владельца локальных данных. Для этого пользователь запуска должен иметь право записи в `data/`. Все временные файлы и кеш matplotlib размещаются в `/tmp` внутри контейнера.

`Dockerfile` использует `python:3.11-slim`, устанавливает `requirements.txt` и запускает `python -m bot.main`. По умолчанию `DB_PATH=/data/bot.db`, `/data` объявлена как volume. Настройки из `.env` передаются через `--env-file`; явный `--env DB_PATH=...` оставляет базу в смонтированной папке.

Логи и перезапуск:

```bash
docker logs -f jeti-nur-reklama
docker restart jeti-nur-reklama
```

Проверьте сохранность данных: создайте тестовый заказ, выполните `docker restart`, снова откройте каталог и аналитику. Файл остаётся в папке `data/` хоста, даже при пересоздании контейнера.

Для изменения токена / whitelist / настроек остановите и удалите контейнер, затем повторите `docker run` с тем же bind mount:

```bash
docker stop jeti-nur-reklama
docker rm jeti-nur-reklama
```

При обновлении кода также повторите `docker build`. Эти команды удаляют контейнер; папка `data/` хоста остаётся прежней. Данные не следует хранить только во внутренней папке `/app/data` контейнера.

На сервере используйте работающий Docker daemon и политику `--restart unless-stopped` для восстановления процесса после сбоя / перезагрузки. Неверный или отозванный токен нужно заменить: процесс завершится с ошибкой и записью в логах, сам действующий токен появиться не может.

## Проверка v1.1 вручную в Telegram

1. Остановите прежний процесс, запустите `python -m bot.main`, отправьте `/menu`. Внизу должны быть только две вертикальные кнопки. В Menu проверьте семь команд, включая `/edit`, `/language` переключает ru/ky.
2. Откройте каталог: без заголовка, жирные карточки и только одна «✅» под каждой. Добавления здесь нет; при пустом каталоге — подсказка `/edit`. Отправьте `/edit`: заголовок режима, карточки «✏️ / 🗑», внизу пояснение и добавление. Добавьте, измените имя/цену, отмените и подтвердите удаление тестовой карточки: после каждого действия должен открываться редактор. Проверьте ru и ky, неверную цену, отмену формы и переход обратно через «📋 Каталог».
3. Выберите продукт: посторонний текст/стикер удаляется с напоминанием, фото/PDF сохраняет заказ. Проверьте «Назад» и `/cancel`: без чека заказа нет.
4. `/deleteorder`: отдельные карточки с датой `ЧЧ:ММ · ДД.ММ.ГГГГ`. «Удалить» редактирует выбранную карточку; «Нет» возвращает её, «Да» помечает заказ удалённым. Для 11+ заказов проверьте стрелки и номера 11, 12… на второй странице; для 10 и меньше стрелок нет.
5. Аналитика: выберите сегодня, 7, 30, всё время; в ручном вводе попробуйте `0`, `100`, `2.5`, затем `1`, `15`, `99`. Неверные значения повторяют вопрос, `/cancel` отменяет. После выбора сразу сводка и четыре раздела, период повторно не спрашивается.
6. Проверьте топ, белый график, список с чеками и пагинацию; удалённый заказ нигде не учитывается. Перезапустите бот и нажмите старые кнопки под сводкой и стрелку списка — период сохраняется.
7. Экспортируйте Word на ru и ky: откройте в Word/LibreOffice, проверьте светлую страницу, таблицы разной ширины, график, подпись, итоговую строку и номера страниц. Пустой период — документ без таблиц/графика; чеков и текста `Asia/Bishkek` в документе нет.
8. Вне форм отправьте текст, голосовое, видео, GIF, контакт, фото/PDF: они удаляются. Ожидаемый ввод форм и команды должны оставаться. Проверьте продукт с `&`, `<`, `>` в названии — текст выводится буквально.
9. `/backup` продолжает отправлять SQLite-копию. Со второго аккаунта вне whitelist функции и удаление сообщений не выполняются; `/myid` доступен. Docker и постоянный том работают по инструкции выше.
